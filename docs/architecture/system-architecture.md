## 1. Data model (Drizzle tables)

Multi-tenant since the auth-core + tenancy migration: **`users`** (`id uuid PK`, `email text UNIQUE` (normalized lowercase at the repo boundary), `passwordHash text` (argon2id), `role 'user'|'admin'` (written explicitly at insert, no column default), `createdAt`) and **`sessions`** (`id uuid PK`, `userId FK → users ON DELETE CASCADE`, `tokenHash text UNIQUE` (SHA-256 of the opaque cookie token — a DB read never yields a usable token), `createdAt`, `lastUsedAt`). Every table below except `sources` carries a NOT NULL `userId FK → users`, and every repo read/write is scoped by it — see api-contract.md §1a.

**sources** — `id text PK` (`greenhouse|lever|ashby|workday|jobstreet|hiredly|maukerja`), `kind 'ats'|'board'`, `persona 'remote'|'local'|'both'`, `enabled bool`, `config jsonb` (slugs, endpoints, query presets, **geo annotations** — 2026-07-12 eligibility spec §6: boards carry `country` (ISO-2), ATS rows carry `geo {scope 'anywhere'|'restricted', regions?}`; `parseSourceGeo` throws on a missing/invalid annotation), `createdAt`.

**profile** — **per-user** (`id text PK` (populated with `crypto.randomUUID()` on upsert; legacy `text` type from the pre-migration `id='default'` singleton), `userId FK → users` UNIQUE via `profile_user_id_unique` — no longer the single-operator MVP's `id='default'` singleton): `baseCountry text` (ISO-3166-1 alpha-2, `'MY'` at registration), `relocation 'stay'|'open'`, `createdAt/updatedAt`. `profileRepo.get(userId)` throws `ProfileMissingError` when the caller has no row yet (no runtime default); `profileRepo.upsert(userId, ...)` is the onboarding path — a fresh registrant's first `PUT /api/profile` creates the row. Parameterizes the eligibility resolver, the scan gating, and the feed predicate (2026-07-12 spec §4/§7), now per-user.

**resumes** — `id uuid PK`, `userId FK → users`, `rawText text`, `structured jsonb` (donor `ResumeStore`: `name, contact[{label,value}], summary, experience[{company,title,dates,bullets[],location?}], education[], skills[{label,items}], extras[]`), `originalPath text?` (relative upload key, see §6.5), `sourceKind 'pdf'|'docx'|'paste'`, `atsScore numeric?`, `isActive bool`, `createdAt/updatedAt`. Partial unique index `resumes_user_id_active_unique` on `(userId) WHERE isActive` — one active résumé per user, not one globally. **Reconciliation:** frozen §5 `Resume` (`headline, location, summary, experience, skills[]`) is a *view* derived from `structured` (headline/location from contact lines, skills flattened). Donor shape wins for storage (richer); frozen shape wins at the API boundary.

**search_runs** — `id uuid`, `userId FK → users`, `resumeId FK`, `personas jsonb` (both on upload), `status 'queued'|'running'|'completed'|'failed'`, `stats jsonb {scanned, matched, scored, ghosts, perSource[{sourceId,found,errors}]}`, `startedAt/finishedAt`, `error text?`. Feeds frozen `ScanStats`.

**jobs** — `id uuid`, `userId FK → users`, `dedupeKey text` (normalized URL) with UNIQUE `(userId, dedupeKey)` — dedupe is scoped per user, not global; two users pasting the same posting URL each get their own row — `url text` (canonical posting), `applyUrl text?` (resolved redirect), `sourceId FK`, `externalId text?`, `title, company, location`, `salaryRaw text?`, `description text?`, `postedAt?`, `firstSeenAt, lastSeenAt`, `persona 'remote'|'local'|'pasted'`, `eligibility 'anywhere'|'eligible'|'local'|'abroad'|'unknown'` + `eligibilityEvidence text` (2026-07-12 spec §4 — stamped at ingest by `resolveEligibility` (board country stamp → JD facts → connector geo → source prior → unknown, pure, zero LLM), refreshed by the scoring path with jd-extract's `hiringScope`/`hiringCountries`; facts stay in `raw`/`jd_facts` so tiers are recomputable via `npm run eligibility:recompute`), `aliases jsonb [{sourceId,url}]`, `raw jsonb`. **Reconciliation:** the donor has *no* `scan_jobs` DB table — scan state lives in `scan-history.tsv` (file plane). Spec §6's "lifts directly" is wrong here; spec §3's no-file-plane rule wins: the TSV columns (`url, first_seen, portal, title, company, status, location`) become this table.

**postings** — `id uuid PK`, `canonicalKey text UNIQUE` (`ats:{sourceId}:{externalId}` else a normalized-URL key — the re-crawl stability key: `ON CONFLICT` bumps `lastSeenAt` instead of inserting a duplicate), `url`, `applyUrl?`, `sourceId FK → sources` (canonical source, collision winner), `externalId?`, `title, company, location`, `salaryRaw?`, `description?` (full JD at crawl time, ≤40k cap; structurally excluded from the stage-1 matching projection so a scan never drags it), `postedAt?`, `firstSeenAt/lastSeenAt`, `delistedAt?` (null = live), `persona 'remote'|'local'|'both'` (copied from the source row at crawl), `tzBand` (`resolveTzBand(location)`, profile-independent, stamped at crawl), `functionTag`/`functionTagVersion` (P.4 coarse classifier write-back cache), `department?` (vendor-stated, kept in the matching projection), `aliases jsonb` (cross-board sightings, merged not replaced), `raw jsonb`. **2026-07-17 global-postings-pool cutover:** the shared, system-owned crawl result — ONE row per opening across all users, no `userId` column. Per-user `jobs` rows are materialized match-views admitted from here (`jobs.postingId`); eligibility/`hiringStructure` deliberately do NOT live here (both are profile-relative). `postingsRepo.listForMatching(persona)` is the stage-1 scan read (live rows, persona-scoped, closed projection excluding `description`/`raw`/`aliases`); `getForScoring` is the full-row read for the admitted TOP_N.

**crawl_runs** — `id uuid PK`, `startedAt`, `finishedAt?`, `status 'running'|'completed'|'failed'`, `stats jsonb?` (`{sourcesOk, sourcesFailed, perHostBackoffs, upserts, delists, durationMs, emptyFetches[], ...}`, null while running). System-owned, no `userId`, one row per crawl run (not a queue) — the crawl-run health + overlap lease (2026-07-17 spec §7.2): a young `'running'` row blocks a second crawler from starting (F6 double-crawler guard), and the latest successful row is the "last successful crawl" fact the F4 48h-staleness SSE warning reads.

**`resolveTzBand`** (2026-07-14 remote-fit spec §5, `src/server/score/tzBand.ts`) — a second pure resolver beside `resolveEligibility`, same log-never-guess shape. Normalizes a stated TZ requirement (authority) or a location-string token (fallback) into a coarse `TzBand` (`apac|emea|americas`; bare TS type, not a wire field — spec §3 "zero new Job fields"): a curated `SAFE_TOKENS` table (PST/PDT/MST/MDT/EST/EDT/"US hours"/"North America"/LATAM → `americas`; CET/CEST/GMT/BST/UTC/"EU hours"/EMEA/Europe → `emea`; SGT/MYT/AEST/AEDT/JST/APAC/Asia → `apac`) is checked in both sources, while `STATED_ONLY_TOKENS` (bare `ET`/`PT` — collide with country codes Ethiopia/Portugal) is checked only in a stated requirement (trust-killer guard: `"Lisbon, PT"` must never map). `"CST"` (US Central vs China) and `"IST"` (India/Israel/Ireland) are permanently ambiguous → `null` + `console.warn`; an unmapped *stated* token likewise warns (curated-map drift signal), but an unmapped *location* string does not (most locations carry no TZ token). The non-logging `probeTzToken(text, source)` is the same lookup for the recompute scavenge, which must stay silent on ordinary country names. Two pure gate mappings consume the band: `allowedBandsFor(scheduleFlex)` — `base-hours → [apac]`, `flex-evenings → [apac, emea]`, `any-hours → null` (all) — and `allowedStructuresFor(employmentPref)` — `employee → [local-entity, eor]`, `local-entity → [local-entity]`, `any → null`. `null` from either always means "no gate condition", never "nothing allowed". `jobs.tz_band`/`jobs.hiring_structure` (nullable, enum-checked) are this resolver's write targets.

**job_scores** — `id uuid`, `userId FK → users`, `jobId FK`, `resumeId FK`, `score numeric(3,1)` (0–5, donor `evaluations.score` CHECK), `verdict text` (`Apply|Consider|Research first|Skip`), `why text` (one-line rationale → frozen `Job.why`; added B6), `legitimacy jsonb {tier, tone, summary, confidence?, signals[]}`, `liveness 'active'|'expired'|'uncertain'`, `breakdown jsonb` (dimensions → frozen `Job.breakdown`), `reasons jsonb {for[], against[]}` (donor `evaluations.reasons`), `fit jsonb`, `gaps jsonb`, `jdFacts jsonb`, `model text`, `escalated bool`, `costUsd numeric(8,4)`, `policyVersion text`, `createdAt`. UNIQUE `(jobId, resumeId, policyVersion)` = the verdict cache. **Reconciliation (revised B6):** the `match-score` template emits the §11.8 **5-tier** vocabulary (`verified|clear|suspicious|ghost|scam`) DIRECTLY (not the donor's 3-tier — the earlier donor→5-tier *mapping* is dropped as it split the prompt and schema vocabularies). `server/score/legitimacy.ts` then applies a deterministic OVERLAY on the model's tier: `scam` wins; liveness `expired`→`ghost`; `verified` only when the model sets `corroborated:true`; otherwise the model's `clear|suspicious|ghost` passes through. `legitimacyTone(tier)` is the single tier→tone source. Frozen `Job` (§5) is assembled in `features/feed` from `jobs ⋈ job_scores` (+ `sources` join for `Job.source`; `sources.name` added B6). `Job.why`/`Job.tags` derive at assembly (`why` from this column; `tags` from `legitimacyTone`).

**applications** — `id uuid`, `userId FK → users`, `jobId FK`, `resumeId FK`, `tailoredResumeId FK?`, `answersId FK?`, `stage int 0..3`, `statusLabel text`, `statusTone 'good'|'verified'|'neutral'`, `note text`, `appliedAt`, `updatedAt`. **Reconciliation:** donor tracker statuses are freeform strings in markdown (`StoredAppRow`); frozen §5 `Applied` 4-stage wins, mapped via `features/applied/status-map.ts` exactly as §5 prescribes. No markdown parsing ported.

**application_answers** — `id uuid`, `userId FK → users`, `jobId FK`, `resumeId FK`, `formSource 'ats-api'|'fetched'|'pasted'`, `answers jsonb` — donor `ApplyAnswers` lifted verbatim: `Array<FormField & {answer: string|null, needs_candidate_confirmation: boolean, rationale?}>`, with `FormField {label, field_type, required, limit?, options?}`; `model, costUsd, createdAt`.

**tailored_resumes** — `id uuid`, `userId FK → users`, `jobId FK`, `baseResumeId FK`, `structured jsonb` (ResumeStore, null until completed), `diff jsonb [{section,op,before?,after?,reason}]`, `html text?`, `pdfPath text?`, `status 'queued'|'running'|'completed'|'failed'`, `finalizedAt timestamp?`, `acceptedIndices jsonb?`, `model, costUsd?, createdAt, completedAt?`. Replaces donor `TailorArtifact` file quartet (`cv.html/cv-latex.json/changes.md/preview.pdf`) — LaTeX dropped.

**correlation_reports** — `id uuid PK`, `userId FK → users`, `jobId FK`, `resumeId FK`, `rows jsonb` (one row per JD requirement: `term/status/evidence/reason/note`), `semantic jsonb?` (`{met, buried, gap, total}`), `ats jsonb?` (`{present, total, missing[]}`), `status 'queued'|'running'|'completed'|'failed'`, `model text`, `costUsd?`, `createdAt`, `completedAt?`. The F6 tailor-correlation engine's LLM-classify output (`correlate` template) — requirement-vs-résumé matching, kept separate from `tailored_resumes` (which FKs to it via `reportId`) so the two-signal (semantic + ATS) report is computed once and reused across a re-finalize.

**url_checks** — `id uuid PK`, `userId FK → users`, `url text NOT NULL`, `dedupeKey text NOT NULL`, `status 'queued'|'running'|'completed'|'failed'`, `stage text?`, `jobId uuid? FK → jobs ON DELETE SET NULL`, `alreadyKnown bool NOT NULL`, `needsText bool NOT NULL`, `error jsonb? {code, message}`, `costUsd numeric NOT NULL` (summed per LLM call), `raw jsonb NOT NULL` (stripped/pasted text + acquisition metadata), `attempts int` (orphan-recovery retry count), `leaseExpiresAt timestamp?` (worker claim lease), `createdAt`, `finishedAt?`. The async run backing **F7 — Manual URL check** (2026-07-12 pasted-job-ingestion spec §10); `urlChecksRepo` exposes `insert`, `updateStage`, `complete`, `fail`, `addCost`, `getById`, `markAllUnfinishedAsFailed`.

**credit_ledger** — `id uuid PK`, `userId FK → users`, `delta int` (+grant / −debit, never 0), `reason 'signup'|'purchase'|'admin'|'debit'`, `feature 'scan'|'evaluate'|'tailor'|'resume'|'answers'?` (debits only), `refId text?` (the domain row the debit paid for — `search_runs`/`url_checks`/etc.), `createdAt`. Append-only (membership-credits spec §4.1) — balance is `SUM(delta)` per user, never an updated counter; refunds/corrections are new rows (`reason:'admin'`), never edits or deletes. A unique partial index enforces at most one `'signup'` row per user (the one-time signup bundle). `server/credits` (§2) is the sole writer, via `assertAndDebit`'s guarded `INSERT…SELECT…WHERE` (no `db.transaction` — same libsql `file:` driver constraint as elsewhere).

All shapes are Zod schemas in `src/types` (→ OpenAPI per §12); Drizzle columns bind to them.

## 3. Source-connector abstraction

```ts
interface SourceConnector {
  id: string; kind: 'ats'|'board'; persona: 'remote'|'local'|'both';
  discover(ctx: {targets: RoleTarget[]; since: Date; signal: AbortSignal;
                 onProgress: (e: ProgressEvent) => void}): AsyncIterable<RawPosting>;
  fetchDetail?(p: RawPosting): Promise<{description: string; applyUrl?: string}>;
  extractQuestions?(job: Job): Promise<FormField[] | null>;   // F4 tier 1/2
}
```

`RawPosting {sourceId, externalId?, url, title, company, location?, description?, postedAt?, salaryRaw?}`. Connectors v1: `greenhouse`, `lever`, `ashby` (donor patterns) + `jobstreet`, `hiredly`, `maukerja` (net-new: public search/listing JSON or HTML parse; no login flows). `PersonaToggle` selects `sources WHERE persona IN (active, 'both') AND enabled` and swaps role-preset/language for templates. **F2 dual-search:** the upload-triggered run passes *both* personas — fan-out over the union with `p-limit` (per-connector concurrency 5–10), per-connector timeout, partial-failure tolerated into `stats.perSource`. **Merge/dedupe:** normalize URL → `dedupeKey`; cross-source duplicates matched by `(companySlug, roleTokens-set hash, location)`; when an ATS posting and a board listing collide, the ATS record is canonical (`kind='ats'` wins `jobs.url`), the board URL appended to `aliases`.

## 4. End-to-end flows

**F1 Upload.** Dropzone/paste → `POST /api/resume` (multipart|`{text}`) → `server/resume`: `extractPdfText`|mammoth|passthrough → OpenRouter **`resume-extract`** (cheap; json_schema=ResumeStore) → insert `resumes`, compute `atsScore` heuristic → return frozen `Resume` view → UI edit/confirm screen (keeps donor confirm gate) → kicks F2.

**Nightly crawl (system-owned, decoupled from F2 — 2026-07-17 global-postings-pool cutover).** `npm run crawl:once` (`src/server/sources/crawl.ts`) → `runCrawl()` (`src/server/sources/crawler.ts`): fetches every enabled, non-dead source's connector (`server/search/connectors/*`) under a per-vendor-host limiter, resolves same-opening duplicates via `dedupe-global.ts` (`canonicalKey`/`crossBoardKey`/`resolveCanonicalCollision`), and upserts one row per opening into the shared `postings` table (`ON CONFLICT(canonicalKey)` bumps `lastSeenAt`; no `db.transaction`, drained through one sequential writer queue — arch §2.3) plus a `crawl_runs` row recording the run's stats/health. Runs once/day via cron (frequency is a cron dial, not code), entirely independent of any user request — no per-scan connector fan-out remains anywhere in the codebase. A failing source is recorded and skipped, never aborts the run; a 403/429 stops that vendor host for the night.

**F2 Search+score.** `POST /api/search {resumeId}` → create run (requires the caller's `profile` row to exist — `ProfileMissingError` aborts before any fetch) → **read the pool** (`server/search/run.ts`): `postingsRepo.listForMatching(persona)` returns live, persona-scoped rows from the shared `postings` table the crawl above already populated → `roleFuzzyMatch` pre-filter (free, uniform across every source kind, since the crawler fetches whole boards unscoped) → function-tag write-back (`ensureFunctionTag`, cached on the posting so later scans read it free) → `admitSurvivors`: resolves the ingest eligibility stamp per candidate (`resolveEligibility` over source geo annotation + posting location), drops `stay`-gated `abroad` rows before ranking (spec §5), rank-demotes by `tz_band`, slices top-N (cost cap), and materializes the admitted slice into per-user `jobs` rows stamped with `postingId` → `scoreTopCandidates`: per job, liveness probe + **`jd-extract`** (cheap → JdFacts incl. `hiringScope`/`hiringCountries`) + eligibility Layer-C refresh (`jobsRepo.updateEligibility`) + **`match-score`** (cheap, `shouldEscalate` → stronger; EvalScores + 5-tier legitimacy) → `job_scores` → progress streamed via `GET /api/search/:id` (SSE) → `GET /api/jobs?persona&filter` returns frozen `Job[]` for `FeedStream`, scoped to the caller's own jobs and shaped by **one hard gate and two rank signals, all server-derived from the caller's profile** (2026-07-14 remote-fit spec §7, as amended by DECISION A full soft rank, 2026-07-17): relocation eligibility is the only hide (`stay` admits `anywhere|eligible|local|unknown`, hiding `abroad`; `open` applies no condition; pasted scope exempt), while stated `tz_band` vs `scheduleFlex` (via `allowedBandsFor`) and stated `hiring_structure` vs `employmentPref` (via `allowedStructuresFor`) demote, never hide — misaligned jobs sort last cross-page via the SQL ORDER BY (P.5 replaced the page-local reorder). A `NULL` band/structure is never demoted, and either resolver returning `null` means no demotion. `stats.excluded` counts only what relocation hid — flipping a dial re-scopes instantly, zero rescan.

**F3 Apply-out.** Feed row "Open" → plain `<a target="_blank" rel="noopener" href={job.applyUrl ?? job.url}>`. No server round-trip (optional `POST /api/jobs/:id/events {opened}` for funnel data).

**F4 Question assistant.** Job detail → `POST /api/apply/questions` → `server/apply-assistant.extractQuestions` (tiers §5) → `FormField[]` → user reviews → `POST /api/apply/answers {fields}` → **`question-answer`** template (mid-tier; grounded on ResumeStore + JdFacts; unanswerable fields get `answer: null, needs_candidate_confirmation: true`) → `application_answers` row → editable answer cards.

**F5 Mark applied.** "Applied" button → `POST /api/applications {jobId, tailoredResumeId?, answersId?}` → `server/tracker` inserts `stage:0, statusTone:'good'` → frozen `Application` returned; tracker screen `PATCH /api/applications/:id` for stage moves via status-map.

**F6 Tailor.** "Tailor for this job" → `POST /api/tailor {jobId}` → **`tailor`** template (strongest tier: ResumeStore + JdFacts + score gaps → tailored ResumeStore + `changes[]`) → `tailored_resumes` draft → UI diff view → `GET /api/tailor/:id/pdf` → `renderCvHtml` + Playwright PDF; "Use for application" links it into F5.

**F7 Manual URL check.** `UrlEvalBar` "Check" → `POST /api/jobs/check` → sync admission (`resumesRepo.getActive()` → 409 before any spend; `text` > 40k → 422; dedupe hit → 200 `alreadyKnown`) → 202 `UrlCheck` → async `server/url-check/run.ts`: **stage fetching** `fetchPageText(url)` — SSRF-hardened per the 2026-07-12 pasted-job-ingestion spec §7 (scheme + resolved-IP denylist re-validated per redirect hop, ≤3 hops; 2MB streamed byte cap; 40k-char text cap; DNS-rebinding TOCTOU is a documented residual risk, hard blocker before any hosted deploy) — any failure or a thrown extract-gate escalates to tier 2, never fails outright → **stage searching** `url-check-search` (sonar) locates the specific posting; `found:false` fails `FETCH_BLOCKED` (`needsText`); `isJobPosting:false` on the found content fails terminal `NOT_A_JOB_POSTING` → **stage persisting** `jobsRepo.upsertByDedupeKey` (`sourceId:'manual'`, `persona:'pasted'`) + eligibility stamp from the precomputed `jdFacts` (Layer C available at ingest) → **stage ghost-check** `ghost-web` (sonar) posting-history sightings; a thrown call never fails the pipeline — `webEvidence:{status:'failed', reason}` and scoring proceeds → **stage scoring** `scoreJob({precomputedJdFacts, livenessOverride, webEvidence})`, with the deterministic repost/corroboration overlay in `resolveLegitimacyTier` (spec §9) → `url_checks` row completes with `jobId`. `UrlEvalBar` polls `GET /api/jobs/check/:id` (~1.5s) and streams stage text. **Boot sweep:** `urlChecksRepo.markAllUnfinishedAsFailed()` runs from `instrumentation.ts` `register()` beside the existing search-runs sweep — without it a restart leaves the poller hanging forever (the tailor path has the same latent gap, not fixed here). Pasted jobs are never `isNew` (no scan-run cutoff exists for the scope) and are exempt from the eligibility visibility predicate in their own feed scope (spec §2.10/§2.12).

Model tiers (`config/models.yml`): `resume-extract`, `jd-extract`, `match-score` = cheapest viable with `match-score` escalation; `question-answer` = mid; `tailor` = strong; `url-check-search`, `ghost-web` = `perplexity/sonar` (F7 only). `policyVersion` = template-file hash → score cache invalidation (unaffected by F7 — `match-score.md` is untouched).

## 5. Hard problems

**F4 — getting external form questions.** V1 is three-tiered: **(1) Structured ATS APIs** — Greenhouse `…/jobs/{id}?questions=true` returns the real form schema; highest fidelity, zero scraping. **(2) Headless fetch + DOM parse** — port donor `extractFieldsInPage` (walks `#application_form`/`.application--form`, strips `*`/`(required)`, captures `field_type/limit/options`) and extend for Lever/Ashby; server-side Playwright (already in the image for PDF). Fails on bot walls and login-gated boards — JobStreet/Hiredly forms sit behind auth, so tier 2 is effectively remote-ATS-only. **(3) Paste fallback (always visible)** — user pastes form text/JD; a cheap **`question-extract`** template parses it to `FormField[]`. Tier 3 is the universal guarantee. Browser extension = post-MVP.

**Résumé parsing fidelity.** unpdf text-layer only — scanned PDFs throw; surface the error with a paste prompt, no OCR in v1. Mitigate LLM structuring drift with json_schema output + a mandatory edit/confirm screen before the résumé drives scoring.

**Dual-source dedupe.** URL normalization is primary; the real risk is the same role on JobStreet *and* the company's Greenhouse — the `(companySlug, roleTokens hash, location)` secondary key catches most; false merges are low-cost (aliases retained).

**Apply-URL capture.** ATS APIs give canonical URLs (`absolute_url`, `hostedUrl`). Board listings often redirect to an external apply target — on `fetchDetail`, follow redirects (≤3 hops, same-origin-or-ATS whitelist per donor SSRF guard) and store the resolved `applyUrl` separately from the listing `url`.

## 6. Upfront decisions & risks

1. **Résumé file storage:** original bytes to a host disk volume rooted at `CALIBER_UPLOADS_DIR` (a required, fail-loud env var — never `process.cwd()`), path in DB; text+structured in DB. Since the multi-tenant migration, files live under per-user relative keys `{userId}/resumes/{hash}.{ext}` (`resumeKey()`, `src/server/resume/uploads.ts`), and the DB stores that relative key (`resumes.originalPath`), not an absolute path — a host move is a pure `rsync` with zero DB rewriting. No S3.
2. **Search execution:** inline async in the Node process (no queue infra); in-memory run registry keyed by `search_runs.id`; hard runtime cap. A restart kills a run (status `running` → mark stale on boot).
3. **Progress:** SSE (donor `sse.ts` precedent) with EventSource auto-reconnect on `GET /api/search/:id` — the status route sends a retry hint and closes silently when no live handle exists for a non-terminal (queued/running) row, instead of synthesizing an error; the run registry is a `globalThis` singleton so `next dev` route-bundle rebundling can't hide a handle across POST/GET; boot flips both `queued` and `running` rows to `failed` so a truly orphaned row is always terminal.
4. **Auth:** email+password sessions — argon2id password hashes, opaque session tokens stored only as a SHA-256 hash (`sessions.tokenHash`), httpOnly `SameSite=Lax` cookie `caliber_session`. Enforced by `requireUser()`/`requireAdmin()` inside each route handler (never Next middleware) — see api-contract.md §1a/§1b. First admin is seeded from `ADMIN_EMAIL`/`ADMIN_PASSWORD` at `db:seed` time. Open registration has no email verification (every account can spend real OpenRouter money) and sessions have no expiry/TTL yet — both are pre-public tripwires tracked in `DEPLOY.md`, not resolved here.
5. **PDF:** Playwright-Chromium baked into the Docker image, invoked in-process — validate the base image in Phase B.
6. **Template/model config:** `config/models.yml` (task→model+escalation) + versioned template `.md` files with Zod json_schemas; template hash = `policyVersion` (also seeds the §11 internal metrics moat later).
7. **DB:** SQLite via libsql (`drizzle-orm/sqlite-core`); embedded file-based in dev/tests; production-ready via Turso. Tests run against temp-file libsql instances for isolation and speed. *(Revised 2026-07-16: migrated from Postgres to SQLite/libsql — single dialect eliminates schema fragmentation, and libsql's local-first approach simplifies deployment without sacrificing Turso's remote/edge capabilities.)*
8. **Cost cap (Gate #5):** per-run score cap (~40 jobs, raised from ~30 post-pool-cutover) + daily cap env var (`CALIBER_DAILY_LLM_USD`); `costUsd` recorded per score/answer/tailor row from day one. The daily cap stays **global across all users** post-migration — a deliberate tripwire, not yet per-user (`DEPLOY.md`: "one heavy user pauses everyone's queue... make it per-user before a paying stranger").
9. **Single-process deploy constraint (post-migration):** decision #2's in-memory SSE run registry and the single `url-check` worker (started from `instrumentation.ts` `register()`) are both process-local state with no cross-instance coordination — running more than one app process (a PM2 cluster, `docker compose --scale`, etc.) silently breaks SSE streaming for runs handled by another instance and lets two workers double-claim `url_checks` rows. Exactly one app process, documented as a hard constraint in `DEPLOY.md`.

Open risk: **MY-board connectors are the only truly unproven component** (no donor code, scraping fragility, possible ToS friction) — build one (JobStreet) first behind the connector interface and let the persona toggle degrade gracefully if a board breaks.
